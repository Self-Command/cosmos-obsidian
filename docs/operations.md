# 运行说明

## 首次连接

打开已绑定的 Obsidian 库，先调用 `inspect capabilities`，确认库名和实际插件能力，再调用 `query model` 读取当前模型。已有笔记的范围和标题由用户确定，同名时展示候选供选择。

任务业务检查 TaskNotes API；周期记录检查 Periodic Notes 对应周期；生命周期检查库内业务服务；发布检查受控客户端及网站契约。安装成功仅表示发现入口和发行载荷一致，不能代替这些业务环境检查。

## 正常写入

业务预览固定实际目标、属性、正文、依赖指纹与执行步骤。用户审阅同一完整预览后才能提交；`--confirm` 是程序接收确认的标志，不能由“创建请求”自动推导。

`review commit` 已包含执行与复检，正常成功后不需要再重复提交。返回步骤中的 `absolutePath` 是实际文件位置，可直接打开。发生环境或内容变化时，旧预览拒绝执行；应重新查看事实后生成新预览。

## 不确定或部分结果

CLI 超时不能证明 Obsidian 应用内操作已停止。拿到 `executionId` 后使用 `execution status` / `execution verify` 沿原记录查询，保留方案、回执及锁，避免重复新建文件或重复上传。

多个步骤可能已有部分完成，文件和插件服务之间没有全局事务回滚。根据原回执区分已完成、失败和未核清步骤；纠正操作同样应生成可审阅的新方案。取消一个已派发的预览不能撤回已有副作用。

## 安装与数据保存

安装器先校验逐文件 SHA256，再将完整发行复制到库外。安装连接记录配置位置，安装方案记录原入口指纹和恢复位置。安装目录、发现目录和状态目录不要作为业务库的子目录。

升级前保留当前绑定、已安装发行与必要状态。安装中断恢复只使用原方案 ID；配置改变后重新生成计划。不要通过编辑内部状态 JSON 或移除锁文件来重放未知操作。

停用或清理时按准确目标确认发现入口属于本安装，再移除链接。目录链接与真实发行目录是不同对象；在 Windows 上不要对未经核实的链接或计算路径执行递归删除。业务库和个人配置的备份由使用者自行管理。

## Amytis 发布

内容创作、公开许可和远端发布分别处理。已有内容的公开副本仅提取已标记的公开区域，来源保持独立；选择整篇公开时，应阅读完整远端正文。

上传预览列出实际公开正文、附件、成员关系和网址。批准本地写作不等于批准上传；专题、系列或书籍包含某篇内容，也不等于给成员公开许可。

上传、PR 合并、部署和页面版本是不同状态。已存在批次使用相应 `resume` / `refresh` 发布预览；网络未知结果先查原执行。清单保存中断需要恢复时，按程序返回的恢复信息建立原批次 `recover` 预览，保留其原分支与提交。

关闭本地 `permission` 或移动本地笔记不会自动撤下已上线内容；撤稿需要独立的撤稿预览、确认及远端读回。

## 反馈问题

在 [GitHub Issues](https://github.com/Self-Command/cosmos-obsidian/issues)提供版本、系统、Node / Obsidian / 相关插件版本、脱敏命令、错误代码和当前执行状态。发布问题应说明失败发生在登记、上传、合并、部署还是页面验证阶段。

必要时附上脱敏后的最小回执片段。不要公开实际绑定、令牌、私密正文或整份本地状态；`COSMOS_TRACE=1` 的性能记录也由使用者检查后自行决定是否分享。
