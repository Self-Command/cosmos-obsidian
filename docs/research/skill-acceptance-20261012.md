# 十技能按架构验收

2026-10-12 用户补充要求：每个技能测试多个场景，并明确以符合技能架构流程为验收标准，不因过度严格而持续重复测试。此要求更新设计 1.0 中将三次速度样本、响应次数和零额外探索作为发行阻断条件的部分。

## 本轮固定范围

每个技能执行三个不同场景，共 30 个；不为同一场景重复采样。各场景使用独立的官方持久会话和隔离真实 Obsidian；第一个使用 Codex 原生预载，第二个使用 Claude 原生预载，第三个使用 Codex 自然发现。固定模型与推理配置保持 `gpt-6-luna / xhigh`。

## 判定与证据

验收判断技能能否采用合法业务入口完成指定职责。读操作和纯咨询不得生成业务变更；写操作须先生成可审阅的实际预览，得到该预览的确认后才提交。产物和关系必须与批准方案一致，其他业务笔记保持不变；取消不复活，中断后读取原执行而不重复派发。具体已给事实应保留，未知与尚未执行的内容不得冒充已确认结果。

响应数、耗时、额外帮助查询和额外技能加载继续保存，用于定位问题，不单独阻断发行。必要澄清、适用技能间的自然路由和接口校验后的修正允许发生。宿主的最大等待预算仍用于让失败可以结束并保留诊断，不将其称为产品速度保证。

保留构建、双平台功能、独立安装、真实 TaskNotes/生命周期/周期记录及真实合成远端发布的检查。Amytis 模型场景不重复执行上传、部署与撤稿；同候选的独立 publication job 继续验证这些操作和恢复。

所有 30 个场景均保存结果；缺场景、重复场景或实际流程/产物失败不能标成通过。先完成固定范围，实际缺陷按影响范围修复复测。最终候选的汇总包含全部场景及证据来源；不为只影响诊断数字的观察重新测试。

只有技能正文变化时，可沿用完整通过且未受影响的真实宿主报告，保留原始 SHA/run 和报告字节，不改写成新运行。必须证明执行器、技能入口、依赖、该技能正文、所有技能的发现描述、场景/宿主控制器、原生环境与夹具完全相同，且报告没有加载已变更技能。发行清单中的源码身份及 SBOM 的 sourceSha 仅为构建元数据；SBOM 的其他内容须完全相同。任一条件不符、原报告失败或证据不完整即重新执行该技能。最终 Actions 重新构建、执行功能/安装/原生/发布检查并复核每份沿用证明，汇总明确标记新执行和保留证据。此方式落实用户要求的按影响范围修复，避免仅改一个技能后反复执行全部模型会话。

场景代码按所选技能的分支及全部共享辅助代码计算依赖；修正另一个技能未执行分支中的测试夹具，不使当前技能证据失效。自身分支、共享控制器、宿主或原生环境变化仍须重新执行。文件移动场景在模型请求前准备其指定的同阶段目标目录，保持业务流程要求；不以缺失的测试目录冒充产品失败。

宿主的有界等待预算延长，不改变此前已经在更短预算内完整通过的场景。等价证明仅允许这一对明确的等待数值增加，完整控制器其他字节必须相同；缩短等待或其他逻辑变化均须重新执行。规划 600 秒、其他阶段 300 秒是本轮运行上限，耗时本身仍仅诊断。

原报告的工具命令、输入、宿主扩展上下文以及工具输出中的完整技能正文用于判定实际依赖。帮助结果中只提到另一个技能的路由名称，不表示加载了它；发现描述仍逐项比较。可指定最近一轮和一个更早的完整场景报告来源，逐份执行同一等价性检查；失败报告不可沿用，连续沿用须先核验前一证明及原始报告字节，再从原始源码重新计算依赖。

审阅前修订可生成新预览，验收选择当前回复实际展示的唯一方案；多个展示方案无法确定批准对象时仍失败。未展示的旧预览保留为诊断，不能自动提交。此前“只生成一份预览且实际展示”的完整通过证据满足新规则；只允许归一化这个精确兼容的选择断言，其他共享代码字节仍须相同。此前未通过的修订场景仍须重新执行批准和原生读回。
