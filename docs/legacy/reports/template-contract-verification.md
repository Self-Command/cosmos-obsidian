# 模板创建修复与复检报告

日期：2026-10-09。验证和安装候选提交：`ebfd1a278c4cfc19cda5059b659f5110ff7ddfd5`。后续报告文档提交不改变安装候选代码。

## 修复结论

问题发生在执行器：现有引擎先创建了正确模板，之后执行器用 AI 提交的自由 `body` 替换全部正文。因而属性正确，模板章节、问题和表格丢失。现有测试笔记保留，本轮不追溯改写。

现在的流程为：需求判断 → 读取已登记的实际模板 → AI 按动态字段填写 → 代码校验并组装完整属性和正文 → 用户审批 → 原有引擎创建 → 读回核验。

普通实体创建在引擎调用 `vault.create` 时一次写入完整文件，不再先创建模板后整篇替换。TaskNotes 和 Amytis 继续使用各自原有服务；同文件生命周期保留既有正文，新建关联实体使用目标模板。日期、标签、路由和关系仍遵循本库 schema。

## 代码门禁

| 约束 | 行为 |
| --- | --- |
| 模板身份 | 绑定源文件、正文、编译字段及 schema 摘要；模板变化使旧计划失效 |
| 模板来源 | 实际文件与系统登记正文不同，拒绝静默使用旧模板 |
| 结构 | 必须提交全部动态字段，拒绝额外字段及固定表头、标签篡改 |
| 可扩展创作 | 允许适合文章的章节名称、重复真实场景、扩展正文和表格数据行 |
| 缺少资料 | 明确 unknown／not-applicable 和原因；预览展示缺口 |
| 正文边界 | 拒绝脱出章节、第二份 frontmatter、模板程序及伪造公开标记 |
| 引用 | 校验实际笔记和附件；不允许不存在的照片占位链接 |
| 绕过保护 | 创建不接受自由 body；同一批次不能创建后整篇替换新笔记 |
| 批次 | 第一次写入前校验整批；第二项无效也不能先写第一项 |
| 结果 | 写入后核验已批准正文及受管理属性，失败保留回执和记录 |

新技能复用 `cosmos_template`、`cosmos_plan`、`cosmos_apply`，无需复制模板骨架。新增模板仍经现有目录与 schema 登记；只修改文件而未同步登记会收到来源漂移错误。提示词负责解释职责，模板约束由程序实施。

这是受控创建通道的结构门禁，不能证明叙述事实或文学质量，也不是通用文件工具的硬沙箱。拥有直接写文件权限的代理仍可能绕过该通道；覆盖所有写入渠道需要宿主权限或钩子。本轮没有擅自限制其他代理工具。
