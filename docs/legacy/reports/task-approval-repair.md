# 任务创建、预览与审批核验修复

## 修复范围

1. 待创建文件以代码文字预览；显示副本将同批尚不存在的关系链接改为待创建文字。保存的执行计划保留真实关联，读回成功后才能给实际文件链接。
2. 区分同名已存在笔记与 0 字节空文件。预览后出现空文件时明确报告 `EMPTY_TARGET_CONFLICT` 和 `dispatch=not-started`；检查不再将空文件漏过。不会自动删除或覆盖。
3. TaskNotes 原生预计时长扩展使用 `timeEstimate`，单位分钟，与 `scheduled` 和 `due` 独立。允许查询、创建和更新；更新可用 null 清除。估算结束时间只出现在预览中。原生 API 写入后验证分钟数，丢失则报失败。
4. 新增只读 `cosmos_approval`。应用和发布门禁从原生 Claude 会话读取用户消息，验证当前库、会话、对应工具预览与最新用户消息；助手、技能注入、工具结果和旧批准不能充当用户同意。
5. 公开上下文只返回 TaskNotes 的实际优先级 value、label、weight；规划与运行时拒绝未登记值。当前库最高档是“高”，不擅自添加 urgent 或 highest。由技能将“紧急”映射为现有最高档，并解释实际设置。

## 授权来源与边界

原生会话根目录默认取当前用户的 `.claude/projects/<实际库路径编码>`。应用参数不能指定日志文件或提交替代日志。可信外置配置中的 `conversationRoots` 用于部署和隔离测试，不由业务工具修改。用户明确直接执行的原请求可与其后生成的工具预览关联，避免重复批准。

这是记录核验门禁，不是完整沙箱。代理仍需解释真实批准范围；有无限制文件权限的代理可以绕过工具或篡改日志。不同模型厂商均可经 Claude/Claudian 的原生会话适配器使用；Codex、Grok、OpenCode、Pi 等不同宿主尚需实现其原生记录适配，不能自行回退为 `approved=true`。

预览格式约束不能阻止用户主动在其他地方创建同名文件，也不能保证其他插件禁止打开不存在的链接；本轮不修改 Claudian 源码。执行器会拒绝覆盖这种文件并显示准确原因。

## 原事故文件处理

原同名空文件保持原状，不假装任务已创建。旧方案和旧会话记录保留，不自动重跑。用户另行决定回收此空文件后，生成新预览再执行；亦可明确选择新的名称。

## 验收安排

GitHub Actions 构建同一候选包，在 Linux 与 Windows 对原生会话、冒充批准、撤销、空文件竞争、任务时间与模板回归执行自动测试。模型语义测试固定 `gpt-6-luna` / `xhigh`，调用真实规划工具，使用合成数据；不上传私人正文。下载通过的产物后更新外置工具及十个共享技能，不本地构建。

实际 Claudian 对话及 Obsidian TaskNotes 写入仍需用户测试；CI 模拟宿主不冒充实机验收。最终结果另附运行编号及保留文件核验。
