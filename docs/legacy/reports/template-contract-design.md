# 动态模板契约与内容填写

## 问题与采用的方法

旧执行器先调用现有引擎创建正确模板，然后用 `op.body` 替换全部正文。属性仍然正确，模板的章节、写作问题和表格却丢失。修复放在读取、生成和执行接口中，不能只追加一段“请遵守模板”的提示词。

采用动态表单契约、确定性渲染及执行前后门禁。Markdown 模板仍是源头，不建立一份写死的18类章节清单。AI 读取当前模板和写作提示，提交可填写位置的内容；程序负责章节、字段标签、表头、只读代码、属性与文件创建。新增技能只复用接口；新增分类模板通过现有 schema 登记，重新读取便可生成新契约。

参考依据：[JSON Schema required 与 additionalProperties](http[本机路径已脱敏])、[Claude 结构化输出与严格工具输入](http[本机路径已脱敏])、[unified 语法树](http[本机路径已脱敏])、[remark-gfm](http[本机路径已脱敏])、[Obsidian Vault API](http[本机路径已脱敏])。结构化输出可以约束输入格式，内容真实性仍需资料和人的判断；不依赖特定厂商一定支持 strict 参数。

模型评估使用 [Responses 原生函数调用](http[本机路径已脱敏])，向模型提供真实 `cosmos_plan` 输入 schema，并把调用参数送入实际规划门禁；校验失败作为工具结果返回供模型修正。评估只开放规划工具，不开放业务执行或通用文件写入。此前自由 JSON／JSON mode 评估遇到第三方返回格式错误和超时，不能算通过；最终以原生工具调用验收，不替换用户指定模型，也不悄悄修补模型参数。模板填写身份同时包含源文件、编译字段映射及 schema 指纹，防止工具升级后旧字段 ID 含义被误用。

## 数据与流程

1. 根据用户意图读取实时实体与分类，选择普通、书籍研读、Amytis 中英文形态或原生任务／周期创建器。
2. `cosmos_template` 返回模板身份、SHA256、原始正文、注释中的写作要求、动态 JSON Schema、可填写字段及空白填写样例。只读，不创建笔记。
3. AI 按用户信息填写 `content.fields`。每个位置明确为 filled、unknown 或 not-applicable；缺少事实注明原因，不能通过编造填写表格。三级场景可以重复并改为真实场景标题；表格可增数据行，已有标签及表头由代码保留。
4. `cosmos_plan` 校验契约版本与填写数据，程序组装模板正文及规范属性，返回完整审批预览和资料缺口。不接受普通创建的自由 `body` 覆盖。
5. `cosmos_apply` 在宿主中重新读取源模板、检查摘要、再次渲染并与审批结果核对。普通实体仍调用现有引擎；在其完整创建调用中填入渲染后的正文，不再先写模板再整篇替换。TaskNotes、周期和 Amytis 继续使用现有服务。
6. 写入后读回文件，核验确定性正文及系统属性；失败保留记录，不报告全部成功，不重复执行。

## 门禁和自由度

- 章节位置、提示标签、表头、只读查询代码、公开边界和系统属性归代码维护。章节名和重复场景名可调整，AI 不重新复制骨架。
- 普通 Markdown 文本、真实图片及链接可填入文本位置；不允许它们脱出所属章节、插入第二份 frontmatter、伪造公开边界或模板程序。
- 没有 `content` 表示创建空白模板，审批预览明确说明尚未填写；不能冒充已结合用户需求完成的正文。
- 既有文本编辑保留独立职责，不能用同一创建批次的 edit-content 替换新模板。此门禁不宣称成为所有代理文件工具的硬沙箱；拥有直接写文件权限的代理仍可能绕过受控工具，需要相应宿主权限／钩子才能覆盖所有渠道。
- 确定性门禁保证结构和绑定，不把“有字”当成事实正确或文学质量合格。资料缺口和 not-applicable 在预览中可见。模型评估验证是否能理解模板要求，实际创作由用户复核。

## 扩展和迁移

模板路径与正文由实际文件及 schema 双向对照。二者不同报告 TEMPLATE_SOURCE_DRIFT，拒绝静默使用旧正文。模板版本改变使旧填写和已批方案失效。用户维护模板需要同步原有生成器／schema；不会自动允许更换库内执行代码。

所有契约存于外置工具和执行计划，不向知识库添加开发文档。现有用户笔记不批量改写。本轮用合成资料验收16类普通实体、目录变体、书籍研读、任务、周期及中英文发布；真实 Obsidian 用户创建另列待验证。

执行记录包含模板绑定和渲染正文摘要，支持定位“选错模板”“模板漂移”“字段缺失”“正文写入不符”，不在公共 CI 保存用户正文。
