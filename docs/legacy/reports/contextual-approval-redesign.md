# 持续授权与 Claude 多轮执行改造

## 问题与原因

2026-10-09 的真实 Claudian 会话中，用户先说“确认创建”，中断后说“继续”。旧执行器只取最后一条用户消息，并用关键词识别批准，导致之前的真实批准失效。实际未调用 cosmos_apply；不能把计划或空文件说成成功创建。先前规划工具测试未覆盖这一真实多轮路径。

## 本轮设计

技能依据完整对话判断用户意图；代码负责来源、对应方案和并发输入校验。移除自然语言关键词白名单，不再要求批准消息一定是最后一条。默认先预览，批准后同一范围直接执行；中断及继续不会自动撤销批准。取消、咨询、引用中的文字不授权写入；改变范围时按新请求处理。

cosmos_approval 返回预览前的请求和预览后的真实用户消息。代理可选择先前的 messageId。证据记录 reviewedThrough（已阅读的最后一条用户消息）、authorizationMode（原请求直接执行或预览后确认）和 scopeHash（具体方案指纹）。执行器拒绝未核对的新消息、错误来源、错误预览及改变后的方案。读到新增消息后可以沿用仍有效的原批准，不要求用户重复确认。

公开 MCP 接口用一个必填 scope={kind,id} 表达目标，kind 为 plan/publish/refresh，可选会话字段允许省略或 null。避免把互斥 planId/previewId/purpose 放在同层造成无关字段补填。旧 CLI 参数保留兼容；同一范围的新旧表示进入相同来源和指纹核验，不降低执行检查。

来源回执保存于库外 approvals，并返回短 approvalRef。应用工具根据编号读取原文、已读位置及指纹，再执行完整核验。模型不再手工传写长指纹和六个证据字段，减少抄写错误；取得回执本身不构成用户授权。旧内联证据调用保留兼容，错误抄写应重新取得回执，不误导为业务方案发生变化。

这不是把“verifiable=true”当成语义授权：sourceVerified/verifiable 仅证明来源与顺序。取消等意图由代理判断，并用实际模型行为测试验证；拥有任意文件写权限的代理仍可以绕过工具，原生记录核验不是权限沙箱。

模板、目录、属性类型、同名保护、原有服务 API、读回校验和失败回执仍由代码执行。未更改知识库模型、TaskNotes 设置、插件开关或用户笔记。旧请求、旧锁和空文件保留，未重跑用户之前的失败创建。

## 验证方法

全部编译和自动测试在 GitHub Actions。单元及集成测试覆盖来源、方案、最新输入检查、三种继续表达、同名空文件、任务时间与模板。新增 Claude Agent SDK 原生会话测试使用 gpt-6-luna / xhigh，不强制 tool_choice；真实调用读取、MCP 规划、授权和执行工具，并通过 resume 恢复会话。

自动模型测试的 Obsidian 与 TaskNotes 宿主是明确标注的合成环境。它核验真实模型选择和本地文件写入结果，不替代用户电脑上的 Claudian／Obsidian 界面验收。旧的只调用规划工具的测试保留为模板语义测试，不再作为完整执行依据。
