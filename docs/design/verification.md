# GitHub Actions 测试与发布验收

设计草案 1.0。没有已运行的新测试。要求是新技能开发完毕、同一候选编译与全部必需测试通过后才可切换并退役旧技能。

## 1. 构建和候选身份

Actions 的 build job 在锁定 Node、依赖和工具版本下生成一次候选。manifest 包含源 SHA、工作流 run/attempt、发行版本、契约版本、各文件 SHA256 与 SBOM/来源。Windows/Linux、原生插件和模型测试下载此候选运行，不分别打包“等价”候选。

每次源码修改必须产生新候选；之前通过只作历史。最终汇总门禁检查全部指定 job 的 SHA、artifact hash、成功状态和实际用例执行数。不能把 skipped、缺少 secret、基础设施超时或空报告解释为成功。文档提交不宣称运行验收。

## 2. 必需测试矩阵

| Job 类别 | 环境与范围 | 关键断言 |
| --- | --- | --- |
| source/contracts | Actions Linux | 类型、Schema、命令帮助与注册表一致；隐私/许可证；技能格式 |
| domain/workflows | Actions Linux + Windows | 目录/关系/日期/模板/状态；计划和执行日志；并发与失败 |
| cli/transport | Actions Linux + Windows | argv、无 shell、UTF-8、stdin、超时、回执竞态和错库 |
| package/install | Actions Linux + Windows | 包自包含、指纹、十技能、无旧路径；安装冲突与恢复 |
| vault-contracts | 隔离夹具与当前规则/模板契约 | 所有登记实体和模板、合法动作与现有插件职责 |
| native-obsidian | Actions 受控 Windows 原生环境 | 真实 Obsidian CLI、TaskNotes、属性、链接、周期、缓存和回执 |
| publication | 隔离服务 + 测试远端 | 公开范围、身份、批次、上传/恢复/核验，不接触用户发布内容 |
| claude-behavior | 官方宿主，隔离库，指定模型 | 自然发现、实际预览、批准/取消/恢复、产物和速度 |
| codex-behavior | 官方宿主，隔离库，指定模型 | 同上；具体中断能力另行标注，不模拟成原生证据 |
| release-gate | Actions 汇总 | 同一候选全部必需 job 和用例通过，产生可核查报告 |

MCP 若实际交付，则增加该入口与 CLI 的契约等价、发现及代表性会话。只因 CLI 优先不必为本次新建 MCP 服务器；决定舍弃旧 MCP 接口时，迁移需精确解除旧连接。

## 3. 原生 Actions 环境

实施前做最小可行性验证：GitHub 托管 Windows runner 是否能用官方安装包在隔离临时 vault 可靠启动、调用和关闭 Obsidian，以及安装合法来源的 TaskNotes/必要插件。固定版本并记录完整环境，禁止使用用户生产库或用户账号。

若托管环境不能稳定运行，则使用专用隔离 Windows runner，通过 Actions 调度，同样运行指定候选。Runner 配置是独立基础设施，不隐式将用户电脑改成长期 runner；需要实际配置时先提出具体方案。原生 job 不可用时保留阻塞状态，不跳过该层后删除旧技能。

合成插件用于快测和故障注入，但其 API 输出不能代表实际插件写入、缓存和周期行为。真实 UI 不一定是每个动作的断言来源；真实文件、插件 API 读回、链接和运行回执是主要证据，必要场景增加 UI 截图。

## 4. 功能与恢复场景

| 场景 | 必须观察到的行为 |
| --- | --- |
| 单任务，事实齐全 | 一次业务预览；日期/优先级/映射正确；批准后一次提交并复检 |
| 长游记 / 书籍研读 | 按实际模板字段写内容，事实/未知明确，正文有实质内容 |
| 项目及关联任务/成果 | 一个方案覆盖精确文件与关系，不把材料批量搬进项目目录 |
| 生命周期推进 | 仅合法动作，原文顺序保留；新增关联文件与同文件变更区分 |
| 日周月季年 | 各自尺度和真实入口；历史日期的实际落盘路径正确 |
| TaskNotes 重复任务 | 实例/系列行为与日期由真实服务执行，不能普通改 status 模拟 |
| 名称/路径歧义 | 提供最小候选，不先遍历全库选择第一个 |
| 模板/来源/关联改变 | 已预览依赖变化拒绝；无关变化仍可提交 |
| 同名/空文件/并发创建 | 不覆盖、不当作成功新建；锁内检查 |
| 注入与非法输入 | 用户内容保持数据，未知动作/字段、越界路径和脚本拒绝 |
| 批准前、取消、取消后继续 | 业务写入为零；取消不会因“继续”复活 |
| 批准后中断/会话恢复 | 原方案和 execution ID 可找回，已经完成的写入不重跑 |
| CLI 退出但应用仍执行 | 结果不确定；保留状态并查回执，不重复派发 |
| 执行完成、保存结果失败 | 输出实际 execution ID，仍按回执验证，禁止重发 |
| 多动作部分失败 | 明确已完成/失败/未开始；不自动全范围回滚 |
| Amytis 上传后未知 | 保留批次与远端状态，执行适用恢复/核验，不清空清单 |
| 发行独立性 | 隐藏所有旧目录后，安装/发现/功能和恢复仍运行 |

不要求测试与实现逐行相同；用用户结果和不变式断言。每个高影响动作都需错误路径覆盖。既有资料里的通过项只用于生成场景列表。

## 5. 真实模型盲测与速度

评估使用官方 Claude/Codex 宿主执行真实工具选择和持久会话，固定 `gpt-6-luna / xhigh` 基线。不强制 tool_choice，不在系统提示中教 prepare/plan 或新命令顺序；只提供技能发现环境、时区、隔离资源和合理权限。

至少测试自然发现和已加载技能两种条件。不同用例分别验证：材料齐全任务、长游记、查找歧义、多文件项目、生命周期及取消恢复。测试原始用户请求和输入事实均保留于可公开的合成案例；人工内容质量 rubric 与确定性结果分别报告。

性能门槛沿用已讨论基线，先验证其可行性，不通过时不换模型或放宽后宣称完成：

- 材料齐全任务规划 ≤90 秒，完整游记规划 ≤150 秒；批准后提交和复检 ≤60 秒。
- 简单任务预览一个业务命令、批准后提交一个业务命令。长正文允许一个草稿契约查询加一个预览，内部阶段调用不暴露给模型。
- 自然发现的简单规划最多四个完成模型响应；已加载技能最多三个；批准后最多三个。
- 无关目录扫描、重复技能全文、无关规则/模板阅读为零。必要歧义查询与缺少事实的询问单独记录，不按失败伪装禁止。

复杂流程同样检查无关探索；歧义、取消、项目及生命周期可以使用必要的业务查询/校验，不能因此放任技能目录扫描。控制器的操作超时为规划轮次 240 秒、其他轮次 180 秒，含 project-plan/cancel-plan/evolve-plan；这是保存完整结果的最大等待预算，不替代上述关键用例的性能门槛。

每个关键速度用例按同一环境进行三次独立会话，保存每次及中位数/最大值；全部满足规定门槛才通过。网络故障按基础设施失败记录，不隐瞒样本，也不算功能失败；必须获得完整合格运行后发行。

记录总耗时、模型响应回合、宿主工具数、业务命令数、CLI/运行时/读回时间、重复探索和 token 计量（可获取时）。不能仅报服务本身 0.5 秒，或以四次业务调用证明用户体验快。

## 6. 隐私与凭据

新公开仓库不复制旧 secrets、环境或账户文件。实现阶段检查新 CI 所需 secret 名称和授权范围，使用现有可信来源传递，不打印值。带凭据的模型和远端 job 只对受信主分支/受控 workflow_dispatch 开启，不对未信任 fork 执行。

公开报告保存脱敏案例、版本、结果与指标。个人会话和机器绑定不进入 artifact 的公共摘要；完整日志按必要范围和访问控制保存。扫描是发布检查，不代表零风险宣告。

## 7. 发布与最终删除条件

唯一 release candidate 的源码、产物、功能、原生、模型和速度全部通过；发布包已下载核验且独立安装验证。新代码不能有 TODO 代替必需能力、skip 代替必需测试、mock 代替原生结论。

Actions gate 通过后仍需执行精确迁移/切换与只读安装核验。只有[退役计划](migration-retirement.md)闭合，才删除旧文件和旧远程仓库。编译成功不单独触发删除。
