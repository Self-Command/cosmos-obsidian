# 冻结、迁移与旧技能退役

设计草案 1.0。用户已经明确授权：新技能开发完毕且 GitHub Actions 编译及全部测试通过后，删除旧技能本地所有文件和远程旧技能仓库。本文件界定执行条件、精确范围与核验；当前条件未达到。

## 1. 冻结

旧源码固定为 `37118c2365dcf353662509676736ebfe014e2986`，本机安装为 `e196141ab4a76ff4ba3731000e470aa2cc02f3d7`。冻结标签 `frozen-2026-10-11`；旧远程仓库归档为只读。冻结后不修代码、不更新旧技能，不重跑原有不确定业务请求。

冻结期间保留现有安装供用户使用；不是禁用插件或将整个知识库设为只读。源文件、安装包、连接引用及状态保存私有清单。旧 Git 历史临时恢复包仅用于审查和迁移，最终清理同样覆盖。

所有调研结果保存到新仓库；历史文档的旧结论保留并注明被新设计取代。新代码从独立 Git 历史开发，不引入旧仓库作为 submodule、动态 import 或发布运行前提。

## 2. 删除清单的归属

实施阶段生成 retirement ledger，每项记录解析后的绝对路径、内容指纹或链接目标、所有者、必要状态迁移目标及执行状态。清单仅列 Cosmos 旧技能专属对象，禁止用全局 `cosmos*` 通配删除。

| 对象 | 最终处理 |
| --- | --- |
| 旧 `obsidian-cosmos-skills` checkout | 新发行独立性和迁移通过后删除，包括其 node_modules、dist、测试、缓存及 state |
| 旧 `.agents/cosmos-skills` 执行器目录 | 新绑定和安装切换后删除，包括旧配置与维护工具 |
| 旧 `.agents/skills/cosmos-*` 十技能 | 对照冻结/更新清单核验；切换到新文件后删除旧暂存/恢复副本 |
| Claude/Grok/Codex 的旧链接 | 仅解除指向旧目标的链接；保留或创建指向新技能的入口 |
| 宿主中的旧 Cosmos MCP 段 | 精确移除或替换本服务项，其他 MCP、账号、模型、权限保持 |
| 旧安装/下载/构建/性能候选副本 | 逐项辨认归属，必要研究先迁出，再删除全部旧专属文件 |
| 旧私有执行状态 | 先核对运行/不确定项；必要记录迁入新独立存储，旧格式文件删除 |
| 临时旧源码 bundle 和冻结私有清单 | 退役完成后清理旧源与过期清单；新退役结果只留脱敏审计 |
| 远程 `Self-Command/obsidian-cosmos-skills` | 完成下述门槛后删除整个仓库，不能只归档替代用户要求 |

新仓库的调研、继承分析和脱敏验收报告不是“旧技能残留”，需要长期保存。必要历史执行记录可转换为新存储的只读审计记录，但不得保留可执行旧方案或旧源码依赖。

不删除：用户 Obsidian 知识库、库内业务引擎/schema/模板/发布服务、TaskNotes/Periodic Notes/Claudian 等插件、其他技能、用户账户与模型配置、Amytis 网站内容以及第三方项目。旧技能开发涉及的系统业务代码不得因放在本库而误当“旧技能文件”。

## 3. 状态迁移

分类读取旧草稿/计划/请求/回执/锁：已完成、明确未执行、取消、部分完成、运行或不确定。对后两类先查询原回执和实际状态；不确定项未查清不能删除其唯一证据。

新执行器不执行旧计划。已完成和取消的必要记录转换为新审计格式；未执行旧计划标记 retired/stale，需要新的业务预览；部分完成保存具体动作结果，由用户未来请求决定余项。迁移本身不创建或改写业务笔记。

新安装的 stateRoot 和 config 必须位于新独立位置，不再指向旧 checkout/state。迁移前后核对记录数、状态和指纹，并验证已完成请求不会在新“继续”流程中重复创建。

## 4. 切换与回滚窗口

先在库外 staging 安装同一 Actions 候选，验证 manifest、绑定和只读能力。新技能暂不放入全局发现目录，避免同名两个版本同时加载。

随后对旧来源与链接进行带清单的原子切换：暂存旧入口，发布新入口，精确维护链接/可选连接，验证十技能发现、新 CLI、真实库绑定与只读状态。切换失败在删除前按事务恢复，不混合两版本文件。

所有恢复副本都列入最终删除清单。新服务必须在临时隐藏旧 checkout、执行器与状态路径时通过功能和恢复测试；不能只是安装配置看起来正确。

## 5. 最终退役门槛

1. 用户已经审阅并批准设计；全部必需业务能力已开发并有继承审查。
2. 唯一候选的 Actions 编译、双平台、包/安装、真实原生、发布和真实模型/速度全部成功，未 skip。
3. 新包已下载核验，切换完成，十技能与新运行时发现通过，无旧代码或路径依赖。
4. 状态迁移完成，运行/不确定项已核清，研究和必要证据保存于新项目。
5. 实际知识库、模板和其他宿主配置完整性核验通过；安装未产生测试业务笔记。
6. 精确清理清单中全部对象身份和绝对路径复核，待删范围没有无关文件。

满足后沿用用户本轮授权执行删除，不反复请求相同批准。条件未满足则报告哪项缺失，继续必要工作，不提前删除。

## 6. 删除执行与证明

Windows 文件操作在 PowerShell 中完成。每个目标先解析绝对路径，核验与 ledger 一致且位于指定旧目录/精确链接。链接删除只移除链接本身，不能递归跟随到新技能目标；包含用户修改时先分析归属并保存必要内容，不能忽略后强删。

删除本地旧来源与残留后复检新来源、绑定、其他技能和业务库。远程删除前核验 owner/name，确认所有仍引用旧 Actions/发行资产的必要证据已迁存；删除旧仓库后验证 GitHub 返回不存在或明确删除状态，不用网络失败当作删除成功。

若 GitHub token 没有 delete_repo 权限或自动审批拒绝，保留已完成工作，报告具体阻碍和所需最小动作；不删除别的仓库，不假称完成。新仓库只保留新实现、研究与结果，没有旧源码备份。

最终提交 retirement report：新候选 SHA/run/哈希、切换和迁移摘要、每项本地清理结果、远程删除结果、保护对象核验与未完成项。报告完成才表示整个重建任务完成。
