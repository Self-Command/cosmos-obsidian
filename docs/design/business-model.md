## 1. 实体覆盖

下表是当前基线，实际状态与分类仍从绑定库读取。TaskNotes 的当前配置可能进一步决定状态与字段映射；不能凭表格直接写任务 YAML。

| 实体 ID | 职责 | 默认位置 | 允许输入职责 |
| --- | --- | --- | --- |
| note | 速记与灵感 | 星云/分子云/速记；兼容灵感/坍缩 | 来源、形式、状态、标签 |
| resource | 外部资源 | 星云/星尘/笔记 | 真实来源/链接、形式、项目/领域与标签 |
| idea | 构想 | 太阳/原恒星/构想 | 判断目标、可能路径与未知；项目/领域 |
| topic | 待解决课题 | 太阳/原恒星/课题 | 交付问题、边界与解决判据 |
| hypothesis | 假设 | 太阳/原恒星/假设 | 假设、证据及试验条件 |
| project | 项目 | 太阳/吸积 | 目标、范围、里程碑与领域；不关联自己为主项目 |
| task | 单次行动 | 太阳/核聚变 | 当前状态、优先级、开始/截止、时长与实际关系 |
| output | 交付成果 | 太阳/光球 | 交付内容、项目/领域、状态和公开意图 |
| question | 认知问题 | 月亮/新月 | 想理解什么、现有观点、来源与领域 |
| study | 研读 | 月亮/上弦/阅读及合法分类 | 来源、阅读范围、摘录位置与个人解释 |

| validation | 检验 | 月亮/下弦/实践及合法分类 | 预先判据、过程与实际结果 |
| direction | 长期方向 | 地球/地核 | 长期责任与取舍 |

目录按当前二级阶段、已登记三级分类及合法已有更深目录解析；只有唯一分类才能由分类确定实体。不存在分类不能自动创建，新增合法子目录必须列入方案。旧兼容路径只在规则实际支持时接受，不恢复旧编号目录。

## 2. 生命周期与动作

当前 schema 登记的动作如下。实现需结合 `availableActions` 与执行服务核验，不只检查表中类型。

| 动作 ID | 语义 | 模式 |
| --- | --- | --- |
| idea | 速记/灵感/坍缩笔记推进为构想 | 同文件移动、变更类型/状态、补结构 |
| project | 符合来源位置的 note/idea/topic/hypothesis 立为项目 | 同文件推进 |
| question | 速记等推进为认知问题 | 同文件推进 |
| record | 速记等整理为经历记录 | 同文件推进 |
| study | resource/question 创建关联研读 | 新文件，保留来源 |
| knowledge | study 创建关联认知 | 新文件，保留研读与依据 |
| validation | knowledge 创建关联检验 | 新文件，保留认知 |
| output | project 创建关联成果 | 新文件，保留项目 |
| published | 成果标记已发布 | 属性更新；必须核对实际发布语义与证据 |
| archive | task/output 满足资格后转归档 | 同文件移动到当前归档位置 |
| repair-body | 指定当前实体补齐正文 | 保留原文顺序，追加缺少结构 |

不将所有实体都当作同一文件线性推进。任务/成果归档使用明确终态日期和七天窗口，不使用 updated、存放时间或模型猜测日期。模型预留的封存/再激活不登记为可执行能力。

原正文保留并不永久禁止用户明确要求编辑；生命周期默认补结构与用户授权的正文重写是两种动作。补结构不包装原文到“推进前内容”小节，不把构想段移到文末。

## 3. 模板及内容

38 个模板文件包括正文与命令模板，不能全部拿来生成笔记正文。当前历史分类为 25 个正文模板与 13 个命令模板；实施时根据实际调用与目录登记再验证分类，不能仅按文件名或数量硬编码。

正文包括普通实体、日周月季年、游记、书籍研读及 Amytis 文章。schema 中还存在英语及章节/目录等特殊内联模板，不能因为模板目录只有一个 Amytis 文件就漏掉这些契约。

模板规则：固定表格标签和必要结构由代码保留；开放标题和重复分组允许按体裁写作；缺少事实标 unknown 并解释。禁止注入 frontmatter、模板程序或改变公开区间。结构正确不代表内容合格，写作 rubric 应检查具体事实、逻辑和对应业务意义。

研读区分原文、位置、作者观点与个人解释；认知必须有条件和边界；检验不虚构实际执行；游记围绕真实场景、过程、感受和复盘，不要求地图坐标或先建项目。当前用户明确需要正文时不能交付空骨架作为“完成”。

## 4. 插件与外部服务

TaskNotes 接管任务创建、状态、时间、提醒和重复实例，采用公开 API v1 及实际能力/字段映射。Periodic Notes 接管周期行为，新适配器验证各周期与历史日期的真实入口，不伪造已落盘。

Amytis 支持 zh/en 明确语言、文章/认知/随笔/专题/系列/书籍/章节。`site_members` 与 `site_outline` 依现有职责使用，不维护第二份清单。目录及成员分别授权公开；公开区间、标题、身份、网址、附件与上传批次进入方案依赖。

上传、合并、部署上线分开验证；本地改名不改网址，本地移动/归档不自动撤稿。网络未知状态保留批次，不通过清空清单解锁。真实上传测试使用隔离测试远端，不测试发布用户的私人内容。

## 5. 覆盖验收映射

实体/模板列表来自当次绑定库；CI 使用经隐私审查的契约夹具以及原生运行时。每个已登记实体至少有创建/审计语义覆盖；每个实现动作至少有合法、非法来源/阶段、依赖变化和读回覆盖。任务、周期、发布再加其专用服务验证。

有新分类、字段、模板或动作时，明确兼容版本与新增测试。无法解析的真实规则返回不支持原因，不能自动修改库规则以“修好”新技能。
